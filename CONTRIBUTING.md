# Contributing

This is currently a solo trainee project, so this file reflects
practices I follow myself and would expect from future contributors.

## Branch naming
`assignment-<number>` for coursework branches (e.g. `assignment-3-2`),
or `feature/<short-description>` for actual feature work (e.g.
`feature/add-book`).

## Commit messages
Short, imperative summary (e.g. "Add real ADR for Epic decision"), not
past tense. One logical change per commit where reasonable.

## Pull requests
Every change gets a PR into `main`, even solo self-review the diff before merging. Reference which task/assignment it closes if relevant.
